Prompt Lab · Research

Run Object

Overview

Research snapshot · April 2026

A standard schema for prompt runs across providers, models and evaluation sessions, designed for a browser-extension-first product.

1

Vendor tracking

Observability tools split into two camps. LangSmith and W&B Prompts go deep on evaluation and chain tracing; Helicone and PromptLayer sit in the request path and capture latency, tokens and template versions.

2

Storage trade-off

Dexie.js on IndexedDB works everywhere an extension runs but queries nested traces slowly. A local SQLite router queries well but needs a separate host process.

3

Proposed v1 schema

Document-first hybrid: store the raw trace as one document and lift the query paths (provider, model, session, tags, time) to flat, indexed fields.

Decision

Keep everything queryable at the root or in compound IndexedDB indexes. Store messages, raw tool calls and provider payloads as untyped JSON so writes stay fast and never block the main thread.

Scores in this research are the April 2026 team's subjective 0–10 ratings, not benchmarks. Model names reflect that time.

Vendor tracking depth

LangSmith and W&B

Strongest on evaluation metrics, session tagging and multi-step chain tracing. Rely heavily on document and event storage.

Helicone and PromptLayer

Prioritize latency, exact token usage and fine-grained template versioning. Often run as a proxy that captures the raw HTTP request.

Only LangSmith and Helicone were scored; they stand in for each camp.

Storage architecture

Higher is better on every axis.

✓ Dexie.js (IndexedDB)

Best extension compatibility and the easiest to ship. Querying heavily nested JSON such as trace trees is slow, so it needs a document-first schema with flattened, indexed fields.

✕ Local SQLite router

Better relational queries and write throughput, but it breaks the extension-first experience by requiring a separate background host process.

Proposed v1 RunObject

Document-first hybrid

The raw execution trace is one large document. The fields you query by are copied to flat top-level attributes so Dexie can index them.

Indexes

Single indexes on timestamp, provider, model and metadata.session_id; a multi-entry index on metadata.tags.

Not indexed

Messages, choices and tool calls stay untyped JSON blobs, which keeps writes fast.
